# ai-care-measurement

Measuring whether an AI care chat actually helps telehealth patients, and separating what the chat *does* from *who chooses to use it*.

## The question

Is the AI care chat working, and should we ship the new model? Specifically:
does chat use improve resolution and retention, or do chat users just differ
from non-users? And does model v2 improve outcomes without compromising
clinical safety?

## Why it's hard

Higher-risk patients use the chat more often (self-selection), and they also have worse outcomes. A naive comparison of chat users and non-users mixes up the chat's effect with the effect of being a sicker patient.

## Data

Synthetic, generated by [`src/generate_data.py`](src/generate_data.py) (fixed seed, so it can be reproduced exactly):

| Table | Grain | What it's for |
|---|---|---|
| `patients` | patient (20,000) | program, plan, channel, age, baseline_risk |
| `subscriptions` | patient | start and cancel dates: retention and survival |
| `ai_launches` | program | staggered AI launch dates: difference-in-differences |
| `conversations` | AI chat (~64k) | model_version, intent, confidence, escalation, resolution, CSAT |
| `support_tickets` | human contact (~95k) | direct tickets and AI handoffs, with handle time: cost and deflection |
| `qa_reviews` | 5% sample of chats | true intent and answer correctness: model quality and calibration |
| `experiment_exposures` | patient | GrowthBook-style A/B test, model v1 vs v2 |
| `answer_key.json` | | the true effects. Open it only after an analysis |

Built-in features to account for:
- **Self-selection and an unobserved confounder:** risk and a hidden "engagement" trait both drive chat adoption and churn.
- **Staggered launch:** the AI chat goes live for each program on a different date.
- **Escalation threshold:** confidence below 0.50 is always escalated to a human (supports a regression discontinuity design).
- **A/B test with a guardrail trap:** v2 looks better on the headline but escalates symptom concerns less.
- **Non-random CSAT missingness** and **injected data-quality bugs** for dbt tests to catch.

See [ROADMAP.md](ROADMAP.md) for the analyses, mapped to the role.

## Methods

Because the true effects are built into the data, every method is checked
against the answer key, so I can show which approaches recover the truth
and which don't.

## Results

**A/B test (model v1 vs v2): v2 wins on resolution but shouldn't ship as is.**

- Resolution improved 2.1 pts (95% CI 0.6–3.7), driven by logistics questions,
  where v2 is more accurate (77% → 91%) and well calibrated.
- Escalation on symptom concerns fell 4.3 pts (CI −8.8 to +0.3). Not
  significant, but the guardrail was underpowered, and the CI includes a large
  drop in clinical handoffs.
- **Bigger finding:** both models are ~15 pts overconfident on clinical
  questions, and escalation is triggered by confidence. So clinical
  conversations are under-escalated in production today, not just under v2.

**Recommendation:** ship v2 for logistics intents only; recalibrate clinical
confidence or set per-intent escalation thresholds; replace 5% random QA with
stratified sampling that oversamples clinical chats.

**Naive comparison (for contrast):** chat users cancelled at 24.6% vs. 39.9%
for non-users. That 15-pt gap is mostly self-selection and immortal-time bias;
the causal analyses (in progress) estimate the true effect.
